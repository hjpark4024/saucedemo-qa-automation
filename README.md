# SauceDemo QA 자동화 테스트

## 개요
- 테스트 대상: https://www.saucedemo.com (공개된 QA 자동화 연습 사이트)
- 목적: 로그인/장바구니 기능에 대한 블랙박스 기반 리스크 시나리오 자동화
- 사용 기술: Python, Selenium, WebDriverWait

## 테스트 시나리오 및 선정 근거

### 1. 중복 담기 강제 시도
- 배경: 수동 탐색 중 Add to Cart 버튼을 클릭하면 Remove 버튼으로 변경되는 것을 확인하였고, 다수의 상품 구매 케이스에 대한 처리가 고려되어 있는지 의문이 들어 테스트 대상으로 선정함
- 리스크 판단: 테스트 페이지라 간단히 구현됐지만, 실제 서비스에서는 UI가 막고 있는 동작이 실제로는 서버 레벨에서 방어되지 않은 채 우회될 가능성이 있다고 판단함. 특히 자동화 도구나 API 직접 호출로 UI를 거치지 않는 경우, 의도치 않은 중복 처리가 발생할 수 있음
- 결과: 버튼 자체가 DOM에서 Remove로 교체되어, UI 레벨 방지 로직이 아닌 구조적 제약으로 확인됨
- 남은 리스크: 서버 측 중복 요청 방어 여부는 API 레벨 검증이 별도로 필요

### 2. 로그아웃 후 뒤로가기
- 배경: 이전에 다른 서비스(네이버)에서 로그인 후 뒤로가기 시 이전 화면이 그대로 남아있는 것을 경험한 적이 있어, SauceDemo에서도 유사한 현상이 발생하는지 검증이 필요하다고 판단함
- 리스크 판단: 로그아웃 후에도 이전 화면이 캐시로 남아있다면, 공용 PC 등에서 사용자가 로그아웃했다고 생각했는데 실제로는 민감한 화면이 뒤로가기로 재노출되는 보안 리스크가 있음
- 결과: SauceDemo에서는 재노출되지 않음을 확인함. 다만 검증 과정에서 일반 click()이 애니메이션 요소에서 정상 동작하지 않는 문제를 발견하여, JS 강제 클릭으로 우회 검증함

### 3. 로그인 실패 시 입력값 유지
- 배경: 로그인 실패 시 아이디/비밀번호 입력값이 초기화되지 않고 그대로 남아있는 것을 확인함
- 리스크 판단: 보안 권장사항 측면에서 로그인 실패 응답 시 입력값을 초기화하는 처리가 필요하며, 특히 비밀번호가 그대로 남아있는 경우 화면 노출(shoulder surfing) 리스크가 있음. 사용자 편의 측면에서도 실패한 값을 직접 지우고 재입력해야 하는 불편이 발생함
- 결과: 아이디/비밀번호 모두 초기화되지 않음을 확인함

## 실행 방법
python test18.py

## 배운 점 / 향후 개선 방향
- 코드 작성 중 콜론(`:`)과 등호(`=`)를 혼동한 오탈자가 있었으나, 해당 테스트 케이스가 그 경로를 검증하지 않아 에러 없이 통과되는 상황을 경험함. 단순히 "기대 결과대로 출력됐으니 통과"로 결론짓지 않고, 코드 내부의 모든 분기와 대입 로직을 면밀히 재검토하는 습관이 필요하다는 것을 직접 겪으며 확인함
- WebDriverWait와 assert만으로 해결되지 않는 케이스(애니메이션 요소에서의 click() 미작동)를 만나며, 자동화 도구가 항상 예상대로 동작하지 않을 수 있다는 점과 원인을 단계적으로 좁혀가는 디버깅 과정을 경험함
